The most obvious repetition was the shared page skeleton. I copied the same site identity, logo, navigation list, and footer into the home page, guide, four family pages, about page, join page, and 404 page. The repetition felt inefficient, but it made the assignment's point clear: plain HTML has no built-in include system. Even a small wording change in the footer required editing every page, and every copy was another opportunity to introduce a mismatch.

Moving files into the `guide/` directory broke more than I expected. Links that worked from the project root needed `../`, including the logo, shared stylesheets, home page, about page, and join page. The family links also broke when one page was named `soft.html` but the guide linked to `soft-ripened.html`. I also learned that a GitHub `blob` URL is a web page, not a direct image or stylesheet asset, so those URLs could not replace correct local relative paths.

The family image transitions exposed another kind of repetition. Each listing image and its matching hero image need the same class and `view-transition-name`, but every family needs a unique name. A copied class such as `family-image-fresh` on the hard-cheese page silently prevents the intended morph. Previous and next links create a similar maintenance problem because one filename change affects several pages.

I would want a tool to generate the shared skeleton, calculate relative paths, and fill page-specific content into templates. For the family pages, it should generate the four pages from one data file, including titles, descriptions, image paths, transition names, and previous/next links. I would also want automatic checks for missing files, broken internal links, duplicate transition names, inline styles, scripts, required metadata, and body-child order. Those features are exactly what web components and static-site generators could provide while still producing simple HTML and CSS.
